# unplugin-linkjs

A plugin for automatically generating manifest.json files when building JS packages with tsdown, rollup, vite, webpack, etc.

## Features

- Automatically generates `manifest.json` from your `package.json`
- Supports multiple build tools (tsdown, rollup, vite, webpack, esbuild, etc.)
- Extract only external dependencies (dependencies excluded from the bundle)
- Automatically writes to build output directory (`outDir`)
- Extensible with custom fields

## Installation

```bash
pnpm add unplugin-linkjs -D
```

## Usage

### tsdown

```ts
import { defineConfig } from 'tsdown';
import unpluginLinkjs from 'unplugin-linkjs/tsdown';

export default defineConfig({
  plugins: [
    unpluginLinkjs({
      includeDependencies: true,
      includeDevDependencies: false,
      includePeerDependencies: true,
    }),
  ],
});
```

**Extract only external dependencies:**

```ts
import { defineConfig } from 'tsdown';
import unpluginLinkjs from 'unplugin-linkjs/tsdown';

export default defineConfig({
  external: ['vue', 'react'],
  plugins: [
    unpluginLinkjs({
      includeExternalOnly: true,
    }),
  ],
});
```

### Rollup

```js
import unpluginLinkjs from 'unplugin-linkjs/rollup';

export default {
  plugins: [unpluginLinkjs()],
};
```

### Vite

```ts
import { defineConfig } from 'vite';
import unpluginLinkjs from 'unplugin-linkjs/vite';

export default defineConfig({
  plugins: [unpluginLinkjs()],
});
```

### Webpack

```js
const unpluginLinkjs = require('unplugin-linkjs/webpack');

module.exports = {
  plugins: [unpluginLinkjs()],
};
```

### esbuild

```js
import unpluginLinkjs from 'unplugin-linkjs/esbuild';

await esbuild.build({
  plugins: [unpluginLinkjs()],
});
```

## Options

| Option               | Type                  | Default                                  | Description                        |
| -------------------- | --------------------- | ---------------------------------------- | ---------------------------------- |
| `shared`             | `Record<string, any>` | `{}`                                     | Shared dependencies configuration  |
| `shareScope`         | `string[]`            | derived from `shared[*].scope`           | Share scopes this remote participates in (written to the manifest) |
| `publicPath`         | `string`              | –                                        | Static CDN base URL for this remote's assets (written to the manifest) |
| `mode`               | `'development' \| 'production'` | `'production'`                | Producer mode written to the manifest (dev server serves `development`) |
| `consumeTypes`       | `ConsumeTypesOptions` | –                                        | Host side: fetch remote `.d.ts` and generate typed `loadRemote` declarations |
| `isReplaceLinkjs`    | `boolean`             | `true`                                   | Whether to replace linkjs imports  |
| `generateSharedFile` | `boolean`             | `true`                                   | Whether to generate shared.js file |
| `extensions`         | `string[]`            | `['.js', '.jsx', '.ts', '.tsx', '.vue']` | File extensions to process         |

**Note:** The `entry` field in the manifest is automatically generated by scanning the output directory. You don't need to configure it manually.

## Generated Manifest

The plugin generates a `manifest.json` file in the build output directory (`outDir`) with the following structure:

```json
{
  "name": "your-package-name",
  "version": "1.0.0",
  "description": "Package description",
  "entry": {
    "js": "./lib.js",
    "css": "./style.css",
    "shared": "./shared.js"
  },
  "expose": ["Export1", "Export2"],
  "shareScope": ["global"],
  "publicPath": "https://cdn.example.com/remote/",
  "shared": {
    "vue": {
      "version": "3.5.27",
      "scope": "global",
      "singleton": true
    },
    "vue-router": {
      "version": "5.0.1",
      "scope": "global",
      "singleton": true
    }
  }
}
```

### Manifest Fields

- `name`: Package name from package.json
- `version`: Package version from package.json
- `description`: Package description from package.json
- `entry`: Entry file paths (automatically detected from output directory)
  - `js`: JavaScript entry file path
  - `css`: CSS entry file path
  - `html`: HTML entry file path
  - `i18n`: i18n entry file path
  - `shared`: Shared dependencies file path
- `expose`: Array of exported items from the package
- `shareScope`: Share scopes this remote participates in (explicit `shareScope` option, otherwise derived from `shared[*].scope`, defaulting to `["global"]`)
- `publicPath`: Static CDN base URL for this remote's assets (from the `publicPath` option; optional)
- `shared`: Shared dependencies configuration
  - `version`: Dependency version (preserves semver range like `^3.5.27` from package.json, except for `workspace:*` which uses `1.0.0`)
  - `scope`: Dependency scope ('global' or 'local')
  - `singleton`: Whether the dependency is a singleton

## Remote type forwarding (`consumeTypes`)

On the **host**, point at one or more remote manifests; the plugin fetches each remote's bundled
`.d.ts` (from `manifest.metaData.types`), caches it under `node_modules/.linkjs/`, and generates a
declaration that types `loadRemote('remote/Expose')`:

```ts
// host vite config
unpluginLinkjs.vite({
  consumeTypes: {
    remotes: [
      { name: 'remoteApp', manifestUrl: 'http://localhost:8080/manifest.json' },
    ],
  },
});
```

Generated (`node_modules/.linkjs/linkjs-remotes.d.ts`):

```ts
declare module 'remoteApp/HelloWorld' { export * from './remoteApp/<hash>-lib'; }
declare module 'linkjs' {
  interface LinkjsRemoteTypes {
    'remoteApp/HelloWorld': typeof import('remoteApp')['HelloWorld'];
  }
}
```

Make sure the host `tsconfig` includes it (default `exclude` skips `node_modules`):

```jsonc
{ "files": ["node_modules/.linkjs/linkjs-remotes.d.ts"] }
// or put a stub in src: /// <reference path="../node_modules/.linkjs/linkjs-remotes.d.ts" />
```

Behaviour:

- **production producer** (`manifest.mode: 'production'`): fetched once at build/dev start (immutable URL).
- **development producer** (`manifest.mode: 'development'`, e.g. served by `tsdown-plugin-server`):
  the host subscribes to `/__linkjs/events` (SSE) and refreshes on `types-changed`.
